# VIDYALINK AI integration

The production flow is:

```text
React client  →  Node/Express API on :5000  →  FastAPI AI service on :8000
```

The React app never calls FastAPI directly and never receives AI-provider credentials. Node owns authentication, authorization, database reads/writes, and the request timeout. FastAPI owns deterministic analysis and returns only analysis derived from the supplied evidence.

## Configuration

Add these placeholders to `server/.env` from `server/.env.example`:

```text
AI_SERVICE_URL=http://localhost:8000
AI_SERVICE_TIMEOUT=30000
AI_PROVIDER=deterministic
```

`AI_SERVICE_URL` is centralized in `server/src/services/ai.service.js`. Connection errors map to `503`, timeouts to `504`, malformed JSON or response shapes to `502`, and no retry loop is used. Node startup does not call FastAPI.

## Internal health

### Node endpoint

`GET /api/v1/ai/health`

No authentication is required. This endpoint reports availability only:

```json
{
  "success": true,
  "data": {
    "available": true,
    "data": {"status": "ok", "service": "vidyalink-ai"}
  }
}
```

If FastAPI is down, Node remains available and returns `available: false` with a safe message. FastAPI secrets and environment values are not returned.

## Portfolio evaluation

### Node endpoint

`POST /api/v1/ai/portfolio/evaluate`

Authenticated roles: student, faculty, recruiter, admin. A student can evaluate only their own portfolio. Faculty, recruiters, and admins must provide a portfolio id they are allowed to view under the existing product rules.

Request:

```json
{"portfolioId": "verified-portfolio-object-id"}
```

Node resolves the existing `Portfolio` record, workspace project, student profile, verified certificates, stored resume text when readable, and connected GitHub snapshot. The portfolio record is the verification gate: it has a faculty verifier and verification hash and is generated by the existing completed, faculty-reviewed workspace flow. No client-supplied project is treated as verified.

### FastAPI call

`POST /api/v1/portfolio/evaluate`

Only the verified project payload is sent. The response is shape-validated before persistence. Scores, component values, evidence, strengths, improvements, and completeness are stored as a new `AIEvaluation` history record in MongoDB. Existing evaluations are not overwritten.

If no verified portfolio exists, Node returns HTTP 200 with:

```json
{"status": "insufficient_evidence", "reason": "No faculty-verified portfolio is available."}
```

No score is saved in this state.

### Stored result

`server/src/models/aiEvaluation.model.js` stores `studentId`, `portfolioId`, `overallScore`, `category`, `componentScores`, `weightedBreakdown`, `evidence`, `strengths`, `improvements`, `dataCompleteness`, provider/model/version, and timestamps.

`GET /api/v1/ai/portfolio/evaluation/:portfolioId` returns the latest stored result, or `{ "status": "not_evaluated" }` without inventing a score. Students can only read their own portfolio result.

## ATS analysis

### Node endpoint

`POST /api/v1/ai/ats/analyze`

Authenticated roles: student, faculty, recruiter, admin. Node reads the student’s stored resume record and extracts text from the stored PDF. A caller cannot replace it with arbitrary text for the student. If there is no readable stored resume, the response is `status: insufficient_evidence` and nothing is persisted.

### FastAPI call

`POST /api/v1/ats/analyze`

Request fields are `resume_text` and optional `job_description`. The validated result is stored in `AIAnalysis` with `analysisType: "ats"`.

## Skills

### Extract

`POST /api/v1/ai/skills/extract` → FastAPI `POST /api/v1/skills/extract`

Node sends actual profile skills, verified project technologies/descriptions, and readable stored resume text. The result is stored as `AIAnalysis` with `analysisType: "skills_extract"`. Extracted skills are analysis only and are never written back into the profile automatically.

### Gap

`POST /api/v1/ai/skills/gap` → FastAPI `POST /api/v1/skills/gap`

Request may provide `currentSkills`, `requiredSkills`, and `targetRole`. If current skills are omitted, Node uses the authenticated student’s stored profile skills. The response contains matched/missing skills, coverage, and recommendations and is stored as `skills_gap` analysis.

## GitHub analytics

`POST /api/v1/ai/github/analyze` → FastAPI `POST /api/v1/github/analyze`

Node reads the connected `GitHubAccount` snapshot. Currently available factual metrics include public repository count and last sync activity. Missing commit/language data is omitted rather than fabricated. A disconnected GitHub account returns `insufficient_evidence`; no synthetic metrics are sent. Stored output keeps `factual_metrics` separate from `derived_activity_score`.

## Industry readiness

`POST /api/v1/ai/portfolio/readiness` → FastAPI `POST /api/v1/portfolio/readiness`

Node loads the latest stored portfolio evaluation, ATS analysis, skill-gap analysis, and GitHub analysis for the target student. Only available scores are sent. Missing components remain absent/null and are not treated as poor performance. The returned readiness result is stored as `analysisType: "readiness"`.

## Recommendations

`POST /api/v1/ai/recommendations` → FastAPI `POST /api/v1/recommendations`

Student-only endpoint. Node supplies actual active alumni profiles and actual recruiter-owned, non-archived project opportunities from MongoDB, plus the student’s stored profile and verified portfolio data. The AI service ranks only supplied entities and returns a reason per recommendation. The result is stored as `recommendations`; it cannot create people, employers, or jobs.

## Frontend behavior

The verified portfolio page calls Node endpoints only. It shows:

- `Not evaluated yet` until a stored evaluation exists;
- a loading state while Node calls FastAPI;
- the actual score, category, component scores, evidence, improvements, and readiness after success;
- an honest unavailable/error message when the service cannot be reached.

Recruiter applicant records include the latest stored AI result when one exists. Otherwise the UI displays `Not evaluated`; it never displays a fallback score or category.

## Authentication and persistence summary

| Operation | Node auth | FastAPI call | Persistence |
| --- | --- | --- | --- |
| Health | none | `GET /health` | none |
| Portfolio | student self; faculty/recruiter/admin scoped | `POST /api/v1/portfolio/evaluate` | `AIEvaluation` history |
| ATS | authenticated target scope | `POST /api/v1/ats/analyze` | `AIAnalysis(ats)` |
| Skills extract/gap | authenticated target scope | `/skills/extract`, `/skills/gap` | `AIAnalysis` |
| GitHub | authenticated target scope | `POST /api/v1/github/analyze` | `AIAnalysis(github)` |
| Readiness | authenticated target scope | `POST /api/v1/portfolio/readiness` | `AIAnalysis(readiness)` |
| Recommendations | student | `POST /api/v1/recommendations` | `AIAnalysis(recommendations)` |
